# Changelog

## 1.0.0 (2026-10-30)

First release. An agent walks the owner of a website through eight security set-up steps, one at a time, in a safe order: their own tested backups, their own copy of the DNS records, the site's email through a proper email service with SPF, DKIM and DMARC, the domain on Cloudflare with the server's address kept private, the protections in front of the site, plugins, themes and scripts kept updated, plugins only from trusted sources, and the Wayback Machine as the last resort. Ground rules: a site the person owns or runs with permission, no secrets in the chat, read-only lookups from the agent's side, one job per message, backups before changes, facts only from the official sources listed, and proof at the end of every step. Ships with the checks reference, the sources list and a progress template.

The eight steps come from a post on r/Entrepreneurs by u/HardenedWeb-Official. Checked against official documentation, three things changed: backups and the DNS copy come first; a domain has to be registered before it can be added to Cloudflare; and the site's email moves before the Cloudflare step, because mail sent from the web server carries its address. Added from the documentation: closing the other leaks of the server's address, locking the server so only Cloudflare reaches it, changing the address after the move, email authentication proven with a test message, and a tested restore.

Tested here (macOS, curl 8.7.1, dig 9.10.6): every lookup in `references/checks.md`, run from the published file against speedrunlab.ai and test fixtures: the proxy check with and without Cloudflare in front, the direct probe's exit codes 0, 7, 28 and 35, the record snapshot, the email records, the DNSSEC lookup, the leak check on a synthetic Cloudflare export, the web-root backup finder and the Wayback lookup. Checked against the tools' own documentation, not run here: the WP-CLI commands, `npm audit` and `composer audit`, the backup commands, the Cloudflare dashboard steps, and curl's exit code 60 on other builds.

Behaviour tested with fresh agents on three owner scenarios: a WordPress shop with its mail on its own server, a Next.js site on Vercel, and a site with spam problems and a nulled plugin on offer. Without the skill, agents answered with every step at once and several questions per message, quoted figures and dated advisories with no source, recommended brands, and one asked the owner for an API token. With the skill, they mapped the setup one question at a time, started with backups, named their sources, and asked for no secrets. The gaps they reported (two-step login, the managed-platform path, an owner already on Cloudflare, mailboxes on the web server, which checks write files, where the progress file lives, DMARC follow-up) were fixed, and a second run of the hardest scenario on the fixed skill found a last set for an owner running cPanel on their own server (which hosting group that is, backing up mailboxes, the mailbox decision before any record changes, testing the certificate before the switch, the quick way back, the panel login, blockers on the server that would ban Cloudflare, and who reads DMARC reports). Those were fixed before release; that second set of fixes has not had a third run.
